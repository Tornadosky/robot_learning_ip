## Metric

`exec-vs-raw`: RMSE (rad) between the joints the robot **actually executed** and the
**raw LAFAN1 clip** at the same reference phase — sign-corrected, mean-centered
(`crosseval_motion.py`, 64 envs × 1000 steps, nominal bodies, no DR). Each arm's own
episode return is NOT comparable across arms (each is scored against its own, possibly
smoothed, reference); exec-vs-raw is. `floor` = the arm's reference's own distortion
vs raw under the same metric — no policy can beat its floor.

Metric validated: baseline's reference floor = 0.055/0.043 (fit residue only), and a
deliberately broken alignment reproduces ~0.9 rad garbage (sign-table trap: the env
flips 13/19 H1 axes on clip load; any offline comparison must apply
`clip_reference.H1_CLIP_SIGNS`/`G1_CLIP_SIGNS`).

## What the self-referenced metrics said (and why they lied)

Episode length / return at 30M: baseline 897/1352, kevin 959/1540, canonical 972/1570 —
the FSQ arms "win". This is an artifact: smoothed references are easier to track and

## Findings

1. **Every policy is pinned just above its reference's distortion floor.** Training
   budget stops mattering once the floor binds (kevin 30M ≈ kevin 98M).
2. **FSQ-as-clip-reconstruction can only converge to baseline, never beat it.**
   With a near-lossless tokenizer (kevin-MC), parity at matched budget
   (0.184/0.136 vs 0.193/0.135 at 30M; 0.168/0.130 vs 0.162/0.122 at 98M).
3. **Tokenizer improvements measured:**
   - Per-joint (kevin) + 6.2× data (10 LAFAN1 clips): recon RMSE **0.21 → 0.041/0.050 rad**. Data was the binding constraint.
   - Longer training on one clip: overfits (eval rises from epoch ~40). Dead end, measured.
   - Canonical + more data: recon **worse** (0.36 vs 0.31). Not data-limited.
   - Canonical + 1M-code codebook: 0.32 vs 0.31, code usage 977→7445 of 9025. Not capacity-limited.
   - ⇒ canonical's ~0.3 rad floor is its **feature set**: 22 task-space dims (root + 4 EEs)
     underdetermine 19–23 joints; the error concentrates in elbows/knees, exactly the
     joints task-space cannot see. Rich-feature ablation (22+19 dims, all else equal)
     running — result below.
4. **Smoother targets are easier RL targets**: tracking overhead above floor is
   0.02–0.04 for lossy-FSQ arms vs 0.08–0.11 for baseline/near-lossless arms.
5. Under morphology randomization the self-referenced FSQ "advantage" grows
   (ep_len +53–61 vs +0–25) — same artifact, larger: smoothed references stabilize
   randomized bodies more. Worth remembering when reading any FSQ-positive ep_len claim.

| 10-clip **rich** (+19 src joints), 1k, 150 ep | 0.373 / 0.336 | 918 |
| 10-clip rich, 1k, 40 ep | 0.383 / 0.346 | 920 |
| 10-clip **rich × 1M codes**, 40 ep | 0.343 / 0.314 | 7573 unique |

Every axis tried — data, epochs, codebook capacity, input features, and their
combination — and the floor never moves below ~0.28. Same URMA decoder family is
near-lossless in the per-joint design (0.04), so the architectural culprit is
**one shared token for all joints**: the decoder cannot recover per-joint detail
from a single code + a 47-dim description. Fix candidates (next session): a few
tokens per frame (e.g., per-limb), or per-joint z with a canonical (embodiment-free)
feature front-end — keeping the cross-embodiment property without the 1-token
bottleneck.

## Where FSQ can actually win — designed next experiment

Reconstruction A/B cannot show an FSQ benefit (finding 2) — parity is its ceiling. The
benefit must come from the **latent itself**:

1. **z-conditioned policy (SONIC-style), multi-motion**: feed the FSQ code stream into
   the policy observation via urma2's `tracking_latent` seam instead of decoded qpos
   targets. One policy, many clips indexed only by z; new motion at test time = new
   token stream, no reward/clip machinery. The multimotion plateau (clip-id one-hot
   failed) is exactly the experiment this design retries with a semantic motion code.
2. **Cross-embodiment shared z**: canonical z decodes per-robot through joint
   descriptions — motion transfer to a new body without retargeting. Needs the
   rich-feature canonical tokenizer (or per-joint z + description-conditioned decoder)
   to clear the fidelity floor first.
3. **Random-bodies synergy**: FK-target pipeline + per-variant decode from shared z —
   the tokenizer becomes the online retargeter the roadmap already wants.

Concrete first step (next session): wire `tracking_latent` to consume
`experiments/fsq_khaendler/clips_kevin_mc/*_zq.npz` (token streams already saved per
clip), train baseline-vs-z-conditioned on 5 dance clips, evaluate on a held-out clip's
tokens. That is an experiment reconstruction-A/B structurally cannot do.
